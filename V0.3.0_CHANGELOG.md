# BOLI v0.3.0 — Changelog (full)

Project follows 0.x semver; each release entry stands alone. See CHANGELOG.md for the canonical log.

## [0.3.0] — 2026-11-18

### Fixed
- **Init string literal size hole:** literals now checked against `BOLI_MAX_STRING_BYTES` at evaluation (previously only `jodo` concatenation was checked). `BOLI_MAX_STRING_BYTES=1` + `likho "abcd1234"` → Galti (was printed).
- **Condition chain SIGSEGV:** unbounded left-nested `ya`/`aur` Cond trees crashed the process (200,000 terms reproduced). Chain capped at parse (`parse_cond`/`parse_aur`) and eval (`eval_cond` depth counter): `BOLI_MAX_CONDITION_DEPTH` (default 128). Hinglish Galti error, line number of the condition, exit 1.
- **Source file read unbounded:** `boli run` now checks metadata length first: `BOLI_MAX_SOURCE_BYTES` (default 10 MiB); larger files are refused with exit 1 before allocation.
- **List size unbounded:** `BOLI_MAX_LIST_ITEMS` (default 10,000) enforced at list literal evaluation and on the `jodo` list-concat result.
- **`pucho` unbounded stdin line:** bounded chunked read; invalid UTF-8 decodes lossy (U+FFFD); over-cap input is a Galti error. (Previously: unbounded buffer; invalid UTF-8 → "input nahi mil raha".)
- **REPL:** incomplete `jab tak` line no longer double-counts block depth (`main.rs` trailing-`tak` rule skips when the line starts with `jab`).
- **Docs:** LANGUAGE_SPEC keyword rule corrected (keywords case-insensitive, identifiers case-sensitive); test counts corrected everywhere; AUDIT_REPORT's false "source-file limit" claim annotated as implemented here.
- **0-arg kaam vs variable name clash:** asking for an expression name that is a kaam with required params now yields "kaam 'x' ko N cheezein chahiye, seedha call karo" instead of the misleading "naam nahi mila".
- **`agla`/`ruk` error lines:** `Flow::Agla` carries the statement's line (ha line-1 hardcode removed).

### Added
- `src/limits.rs`: single module for all safety limits — defaults + `BOLI_MAX_*` env override helpers (`env_limit`).
- `BOLI_MAX_PARSE_DEPTH` (64), `BOLI_MAX_CONDITION_DEPTH` (128), `BOLI_MAX_EVAL_DEPTH` (256) — all env-tunable.
- Parser `with_limits` constructor for deterministic tests; `Environment::with_list_limit`, `with_eval_depth_limit`, `with_condition_depth_limit` (chainable).
- `Expr::line_for_error` for precise depth-limit error lines.
- Tests: `literal_string_size_limit`, `list_creation_limit`, `list_concat_limit`, `list_under_limit_works`, `condition_ya_chain_parse_limit`, `condition_ya_chain_eval_limit`, `deeply_nested_agar_errors_not_crashes`, `deeply_nested_expression_errors_not_crashes`, `deeply_nested_hissa_chain_errors_not_crashes`, `moderately_nested_code_still_works`, `lexer_rejects_control_characters`, `malformed_programs_error_not_crash`, `fuzz_lex_parse_never_panics`, `cli_bogus_subcommand_errors`, `cli_run_with_too_many_args_errors` (+2 deep-nesting fixes from v0.2.x regression batch).

### Changed
- `Expr::Text` evaluation routes through `checked_text` (same 1 MiB policy as concatenation).
- Cargo metadata: `description`, `license = "MIT"`, `repository`.
- Test-count: 71 → 82 (67 library + 15 CLI).

### Internal
- `cargo fmt --check` is now a green gate (one-time reformat, commit `df5c012`).
- `cargo clippy --all-targets --all-features -- -D warnings` clean.
- `cargo build --release` verified; `install.sh` smoke-tested via `BOLI_INSTALL_DIR` override (version reports 0.3.0).

### Compatibility
No `.hl` program valid under v0.2.0 changes behavior. Only previously-crashing or previously-unbounded inputs changed from "crash/infinite growth" to "Hinglish error". Public library API is additive only.

## [0.2.0] — 2026-11-18

### Fixed
- **BUG 1 (P1, parser):** flat call arguments — `f a b` → `f(a, b)` (was nested `f(a(b))`).
- **BUG 2 (P2, interpreter):** range-loop scope always popped, even on error.
- **BUG 3 (P2, interpreter):** count-based range iteration; `9007199254740992 se 9007199254740994 tak` terminates exactly.
- **BUG 4 (P2, parser):** `aur` binds tighter than `ya`.
- **BUG 5 (P2, interpreter/lexer):** NaN/±∞ blocked at literals, `pucho`, arithmetic results — Hinglish Galti instead of inf/nan leaks.

### Added
- Runtime limits `BOLI_MAX_STEPS` (100,000), `BOLI_MAX_CALL_DEPTH` (64), `BOLI_MAX_STRING_BYTES` (1 MiB) — now in `src/limits.rs`.
- `ruk`/`agla` (aliases `break`/`continue`); 1-based `hissa` list index; list literals & `jodo` concat; `barabar` list equality; zero-arg kaam in expressions; negative numbers; `\n` escape; Unicode-mark identifiers; REPL quote-aware depth tracking & stray-`khatam` recovery; SIGPIPE-safe exit 0.

### Changed
- **Semantics:** `rakho` writes innermost scope only (never silently mutates outer/global).

### Internal
- lib/bin split; `AUDIT_REPORT.md`, `LANGUAGE_SPEC.md`, `ARCHITECTURE.md`, `TESTING.md`; 67 tests at the time.

## [0.1.0] — 2026-11-18

Initial public release: lexer, parser, AST, tree-walking interpreter, CLI + REPL, examples (namaste, calculator, calculator2, loop), installer, README, MIT license.
